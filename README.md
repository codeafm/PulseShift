# PulseShift

Unity-проект мобильной игры. Открывать **корневую папку этого репозитория**, где находятся `Assets`, `Packages` и `ProjectSettings`.

## Открытие на Mac

1. Установить Unity Hub и **Unity 6000.3.18f1** с модулем **iOS Build Support**.
2. Клонировать репозиторий:

   ```sh
   git clone https://github.com/codeafm/PulseShift.git
   ```

3. В Unity Hub выбрать Add → Add project from disk → папку `PulseShift`.
4. Дождаться импорта ассетов и восстановления пакетов. При первом открытии нужен интернет для Unity Package Manager / OpenUPM.
5. Открыть `Assets/Scenes/PULSESHIFT_Menu.unity`. Игровая сцена: `Assets/Scenes/PULSESHIFT_Game.unity`. Обе сцены уже указаны в Build Settings.

Все нужные ассеты и `.meta` находятся в репозитории. `Library`, локальные APK, логи и временные сцены восстановления не включены; Unity создаст свой кэш на Mac. Git LFS для этой версии не требуется.

## Следующий этап: iPhone

- Установить совместимый Xcode и его command-line tools; выбрать iOS в Unity Build Profiles и переключить платформу.
- Задать собственный уникальный Bundle Identifier и команду Apple Developer для подписи. Сертификаты, provisioning profiles и ключи в Git не хранятся.
- Проект использует **Yandex Mobile Ads Unity 8.4.0** через OpenUPM и External Dependency Manager. Дождаться восстановления iOS-зависимостей; для CocoaPods потребуется локальная установка на Mac. Если экспорт создал `.xcworkspace`, открывать его, а не только `.xcodeproj`.
- Собирать Xcode-проект в отдельную папку `iOSBuild`, затем запускать на физическом iPhone.
- Перед публикацией проверить рекламу, safe area, звук, вибрацию, приватность и производительность на устройстве.

**iOS/Xcode-сборка и тест на iPhone ещё не выполнены.** Проверка C# или Android не заменяет этот этап. Windows-сборку переносить на iPhone не нужно — сборка делается заново из проекта.

## Реклама

| Платформа | Баннер | Rewarded |
| --- | --- | --- |
| Android | R-M-20061525-1 | R-M-20061525-2 |
| iOS | R-M-20061555-1 | R-M-20061555-2 |

В Development Build используются demo ID; в release — ID выше. В Editor видна пустая панель, реальные объявления не запрашиваются. Размер рекламной области ограничен 350 × 50 dp через `BannerAdSize.Inline` (в текущем Android SDK вызов `Fixed` несовместим с нативным API). Не тестировать клики по собственным production-объявлениям.

Награды выдаются только по событию SDK о завершённом просмотре. В меню: 10 кристаллов либо 1 импульс. В кампании: добровольный бонус после каждой третьей победы на уровнях выше 5. Обновлением баннера управляет SDK.

## Производительность и визуал

- Сохранённая сцена меню — эталон света; дополнительная Play-only тональная обработка там отключена.
- Старые устройства автоматически используют облегчённый режим с целевыми 30 FPS; мощные — до 60 FPS согласно настройке.
- Счётчик устойчивых просадок может включить облегчённый режим на текущую сессию. Он не гарантирует одинаковый FPS на всех устройствах.
- Android-шейдеры и логика выбора режима проверены отдельно. Длительная проверка новой сборки на реальных устройствах остаётся обязательной.

Скрипты кастомных сборок находятся в `Assets/Editor`. Для обычной сборки на Mac также можно пользоваться Unity Build Profiles. Старые вспомогательные генераторы могут ожидать исходники Blender из локального рабочего каталога; для открытия и сборки сохранённых сцен они не требуются.
